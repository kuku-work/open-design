# 怎麼寫受眾輪廓（persona）

給 agent 的寫作指引。輸入檔的 `part1.personas` 要填什麼、每一格該長什麼樣。

---

## 一頁總覽 ＋ 每人一頁，數量由你決定

`personas` 陣列有幾筆就出幾頁人物誌，加一頁三卡片總覽。**不寫死 3 個**——
三個是提案類簡報的慣例（給客戶三個方向），不是規格。兩個、四個都合法。

---

## 每個 persona 的十一格

```yaml
- name: 都市上班族                    # 標籤名稱：一個能一眼分辨的族群標籤
  title: 科技品牌行銷經理              # 職稱：具體到行業＋層級，不寫「上班族」
  person: David                       # 姓名：給一個名字，讓他變成一個人而不是一類人
  narrative: |                        # 3–4 句生活敘述
    工作為 David 平時的生活重心，但同時也追求 work-life balance 的生活方式；
    時常關注各種最新的科技資訊，願意花錢投資在能幫助生活更便利高效的產品與周邊配件。
  background:
    性別: 男
    年紀: 35-39                       # 給區間不給單一數字
    居住地: 台北                       # 城市層級
    家庭狀況: 已婚
    教育程度: 碩士畢業
  consumer:
    興趣: 商業閱讀、科技產品、咖啡文化、烹飪、旅行    # 4–6 個關鍵詞，頓號分隔
    目標: 需要一款時尚又實用的配件來提高生活和工作的效率。   # 一句話
    痛點: |                           # 1–2 句，要能對應到產品解的問題
      工作繁忙，經常在車上、辦公室和會議間切換；
      傳統的攜帶方式不夠靈活和方便，需要能隨時使用手機和常用配件。
    使用社群: LINE、Instagram、Facebook、Threads      # 3–4 個平台
```

⚠️ **`background` 與 `consumer` 的 key 本身也是資料。** 換產業可以換欄位——
B2B 可能要「公司規模／決策角色／採購週期」，餐飲可能要「用餐頻率／同行人數」。
生成器照你給的 key 畫表格，不寫死欄位名。

---

## 四條寫作紀律

**1. 痛點要對得上產品，但不要寫成產品文案。**
✅「傳統的攜帶方式不夠靈活，需要隨時使用手機和常用配件」
❌「需要一款有掛繩設計的保護殼」← 這是解法不是痛點

**2. 興趣不是形容詞，是可查證的行為。**
✅「商業閱讀、科技產品、咖啡文化、烹飪、旅行」
❌「注重生活品味、追求質感」← 這種寫法三個 persona 會長得一模一樣

**3. 三個 persona 之間要真的不同。**
寫完把三個人的「目標」並排看——如果換掉名字就分不出誰是誰，那就是同一個人寫了三次。
差異應該落在**動機**（為什麼買）而不是**外表**（年齡性別）。

**4. 沒有研究就標 null，不要編。**
persona 的來源是訪談、問卷、後台數據。沒有那些就填 null，
生成器會畫出欄位表加空槽——**空著的表格比編出來的人物更誠實，而且看得出還缺什麼**。

---

## 沒有研究資料時，怎麼問出來

問需求方這四題，答案直接對應欄位：

| 問 | 填哪格 |
|---|---|
| 現在買這類產品的人，你們觀察到有哪幾種？ | `name`（族群標籤） |
| 其中最典型的一個，他做什麼工作、幾歲、住哪？ | `title` / `background` |
| 他為什麼會需要這個東西？現在他怎麼解決？ | `consumer.目標` / `consumer.痛點` |
| 他平常在哪裡看到新東西？ | `consumer.使用社群` |

⚠️ 問不出來不是失敗，是產出——把問題列進待問清單，該格留 null。
